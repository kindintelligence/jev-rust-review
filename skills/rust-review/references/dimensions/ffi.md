# FFI

The FFI boundary is where Rust's guarantees stop. Check every assumption about the other side.

## Look for

- **ABI and layout.** Types crossing the boundary need `#[repr(C)]` (or `repr(transparent)`). Function signatures must match the C declaration exactly (integer widths, `c_int` versus `i32`).
- **Ownership across the boundary.** Check who frees what, and with which allocator. Memory from `CString::into_raw` must come back through `CString::from_raw`, not C `free`. Memory from C `malloc` must go back to C `free`, not `Box::from_raw`.
- **Nullability.** Pointers from C can be null. Check them, or use `Option<NonNull<T>>` / `Option<&T>` / `Option<extern "C" fn>` in signatures.
- **Strings.** C strings need a NUL terminator (`CString::new` fails on interior NULs), and `CStr::from_ptr` needs a valid, terminated pointer. The encoding must be agreed; do not assume UTF-8 without checking.
- **Panics crossing `extern "C"`.** A panic unwinding out of an `extern "C"` function aborts on recent Rust. Use `catch_unwind` at the boundary, or `extern "C-unwind"` when unwinding is intended.
- **Lifetimes.** A pointer handed to C must outlive C's use of it. `as_ptr()` on a temporary `CString` dangles immediately.

## Do not flag

Bindings generated by `bindgen` that the change did not modify.

## Evidence that makes it a finding

The concrete misuse. For example: "`CString::new(name).unwrap().as_ptr()` passes a pointer to a temporary that is dropped at the end of the statement."
